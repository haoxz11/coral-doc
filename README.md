# coral-doc

一个 Agent skill：按 coral 文档库的约定撰写 Markdown 并落盘到本地文档库。

仓库地址：<https://github.com/haoxz11/coral-doc> ｜ 安装方式见下方[「安装」](#安装)

它替使用者解决三件事：

- **位置选对**——从文档库现有结构里选一级菜单与目标目录，而不是随便丢一个路径。
- **类型判对**——命中发布意图时仿写库内同类发布文档的固定套路，其余情况按研发视角专业写作。
- **内容写对**——填对 front matter，并用 coral 的 markdown 能力（提示块、选项卡、mermaid 等）把文档写漂亮。

## 三种模式

本技能**只能手动唤起**（见下方「调用方式：仅手动唤起」一节）。被点名调用后，按下面的条件在内部选择模式：

| 模式 | 进入条件 | 做什么 |
|---|---|---|
| 手写模式（默认） | 提出要写文档，未给出其他线索 | 从零撰写一篇新文档 |
| 钉钉导入模式 | 给出钉钉文档链接/ID **且**表达存库意图 | 把钉钉文档转成 Markdown 存入库，图片换长期链接；再次导入时未变更的图片不重复上传 |
| 本地优化模式 | 声明要优化某个本地 md 文件 | 按用户点明的项优化，处理本地图片引用，并默认整理 front matter 头信息 |

只有钉钉链接、没有存库意图时（查询、讨论），不会进入导入模式。

## 前置条件

**必需**

- 一个 coral 文档库。

**按模式可选**

- 钉钉导入模式：优先使用本机已登录的 `dws` CLI；不可用时降级到会话中已配置的钉钉 MCP。两者都不可用会明确告知并停止，不会臆造内容。
- 涉及图片换链（钉钉导入、本地优化）：需要 `coral-mcp`（工具名 `upload_file` / `finalize_upload`）。未安装时，skill 会读文档库首页 front matter 的 `remote_url` 字段定位 coral 服务，走 `{remote_url}/mcp` 端点；两者都拿不到会向使用者询问服务地址。

**关于文档库地址**

文档库地址由使用者在指令中告知，skill **不猜测、不使用任何记忆中的路径**。整个过程中每次回复都会显式引用当前库地址（例如「文档库：`/path/to/content`」）；给出的路径不存在时会先确认正确地址。路径完全取决于使用者，不绑定任何特定团队或仓库。

## 安装

本技能发布在 GitHub：<https://github.com/haoxz11/coral-doc>

装到**跨 agent 的通用 skill 目录** `~/.agents/skills/`，多个 agent 共用同一份。

### 方式一：coral 托管（推荐）

已安装 coral 的环境，直接让 coral 安装并自动升级：

```bash
coral skill install
```

之后每次使用技能时自动检查并升级到 coral 内置的最新版本（`coral skill ensure`）；本地版本比内置新时保留本地版本，不会降级。

### 方式二：git clone（备选）

```bash
git clone https://github.com/haoxz11/coral-doc.git ~/.agents/skills/coral-doc
```

更新到最新版：

```bash
git -C ~/.agents/skills/coral-doc pull --ff-only
```

注意：此方式安装的副本在工作区干净时会被 coral 升级覆盖为内置版本；想保留本地定制，请不要混用两种方式。

仓库里只有 `SKILL.md`、`references/`、`scripts/`、`VERSION` 和这份 README，没有依赖、无需构建（缓存脚本只依赖 python3 标准库）。技能本身遵循通用的 `SKILL.md` + YAML front matter 约定，不绑定任何具体 agent——装到哪个目录由你的 agent 读哪个目录决定。

## 调用方式：仅手动唤起

本技能**不会因为你在写文档而被自动唤起**。它的 front matter 已明确声明「手动调用，禁止自动唤起」，并去掉了此前的触发词清单（写文档、写发版记录、write doc、release notes、提到 coral/文档库 等）。

- 唤起方式：在消息里显式点名 `coral-doc`（或 `/coral-doc`、`coral 技能`），然后再说明任务。
- 未点名时：即使你说的是「写一篇发版记录」「把这个钉钉文档存到文档库」这类原本会命中的场景，也不应自动调用。
- 已调用后：模式判定（手写 / 钉钉导入 / 本地优化）只是技能内部的流程分流，与唤不唤起无关。

## 手写模式工作流

### 1. 选一级菜单

扫描文档库根目录：每个一级子目录读其 `_index.md` 的 front matter，`title` 即菜单名（无 `_index.md` 或无 `title` 时用目录名），`weight` 小者在前、无 weight 沉底；根级 `.md` 文档也是一级菜单项。

使用者已指定菜单或目录时直接采用，但仍会展示最终目标路径供确认。**未指定存放位置时不会甩出全部菜单让使用者自己挑**——而是根据文档内容在库内找出最匹配的 2–3 个候选目录（可深到二级子目录），列出并附推荐理由供选择；确无合适候选才回退到完整菜单列表。

### 2. 意图判定（二选一）

**发布文档**——意图命中「发布 / 发版 / 上线 / release / 部署清单」时：

1. 在所选一级菜单的子目录树中搜索目录名含 `发布` / `release` / `发版` 的目录，找不到扩大到全库。
2. 优先选非归档目录（目录名含 `历史归档` / `历史发布` 的视为归档，仅作参考）；多候选时由使用者选。
3. 取该目录下**最新一篇**（按 front matter `date` 或文件名中的版本号/日期）作为**格式样板**。
4. 仿写样板的固定套路：章节结构、表格列、状态标记、front matter 字段全部照样板对齐，内容按本次实际情况填写。

**专业写作**（默认）——不仿写任何既有文档的格式。以研发工程师视角（架构、测试、运维等研发侧视角，视内容而定）自主组织章节结构（背景/目标/方案设计/影响面/上线计划等，视内容取舍）。

### 3. 填 front matter

| 文档类型 | 字段 |
|---|---|
| 普通文档 | `title`（从正文一级标题或用户意图提炼）+ `date`（当天，`YYYY-MM-DD HH:MM:SS`） |
| 发布文档 | 在普通文档基础上加 `permalink`：样板有惯例则照其模式生成，无则按目录路径生成 |
| 目录分支页 `_index.md` | `title` + `icon`（Iconify 名，带前缀如 `mdi:home`）+ `weight` |

front matter 用 YAML（首行 `---`）。完整字段语义见 [references/coral-markdown.md](references/coral-markdown.md)。

### 4. 动笔前确认

动笔前会展示并等待确认：目标文件绝对路径（库地址 + 菜单路径 + 文件名）、类型判定（仿写哪个样板文件 / 专业写作）、内容大纲（章节列表）。

### 5. 写作与美化

主动使用 coral 的 markdown 能力美化文档，语法速查见 [references/coral-markdown.md](references/coral-markdown.md)。写完后会再自检一遍：正文里是否还有该用这些能力的地方（散落的注意事项、多方案平铺、口头描述的流程），有则改写。

## 钉钉导入模式

详细命令、缓存结构与上传接口见 [references/dingtalk-import.md](references/dingtalk-import.md)。

1. **确定文档库地址、选存放位置**：库地址由使用者告知。**存放位置优先复用缓存**——缓存里已有该文档记录、且使用者未指定位置时，直接沿用记录中的路径，跳过选菜单；使用者给了位置就用使用者的，并更新记录。仅当无缓存记录时才按手写模式的规则选菜单。
2. **读取文档**：`dws doc info` 探测类型，`dws doc read` 取 Markdown 与元信息。仅**普通文档（adoc）**可读；表格（axls）、画板（adraw）、白板（awbd）、多维表（able）等不支持，会告知使用者并建议先在钉钉中转为普通文档。分享短链（`alidocs.dingtalk.com/i/p/{key}`）无法解析，需给出完整链接或文档 ID。同时取出钉钉 `nodeId` 作为缓存主键。
3. **再次导入判定（查缓存）**：`python3 <skill目录>/scripts/imports_cache.py lookup <库地址> <nodeId>` 查导入记录（缓存的读写一律走该脚本，不临场写代码）。
   - 使用者带了**强制意图**（见下）→ 跳过判定，直接重新导入并覆盖缓存记录。
   - 无记录 → 完整导入；有记录但目标文件已不在（被移动/删除）→ 询问：继续导出到缓存记录的目录还是重新指定目录，落盘后记录的 `target` 都会更新为实际路径；有记录且文件在 → 比源文档最后修改时间，相同则**跳过**并汇报导入过的位置，不同则提示「源文档已更新（旧 → 新）」由使用者选覆盖 / 另存 / 跳过（另存后记录指向新文件）；拿不到修改时间时不静默跳过，改问使用者。
4. **图片处理（核心）**：钉钉返回的图片是**临时签名 URL，几分钟内过期**，绝不能原样保留。每张图下载后用脚本 `hash` 算 sha256，**先 `lookup-upload` 查 `uploads` 台账**（按 coral 实例 + 内容哈希）：命中直接复用记录链接、不调上传；未命中才走 `upload_file` → multipart 直传对象存储（文件字段名必须是 `file` 且放在表单最后）→ `finalize_upload`，拿到长期链接后逐张改写引用，不漏改、不错位，并立即 `record-upload` 回写台账。只有台账无法回答（缓存丢失等）且目标文件已存在时，才回退到"下载新旧图片比对哈希 + 按顺序/配对"的兜底逻辑，比对结果同样回写台账。
5. **导不出的内容**（白板等无导出 API 的图类）：保留钉钉原文链接，不强行转换。
6. **正文转义还原**：钉钉导出的 Markdown 会把部分字符写成十进制 HTML 实体（典型是表格单元格代码片段里的 `&#95;`，coral 不解码、会原样显示）。落盘前统一还原（`&#95;` → `_` 等，表格内的 `&#124;` 还原为 `\|`），还原处数计入转换摘要。
7. **front matter**：`title` 用钉钉文档标题，`date` 用钉钉文档最后修改时间（拿不到则用当天）。
8. **文档尾部注明来源**：正文最后追加一行 `> 来源：[钉钉原文 · <标题>](<链接>)`。
9. **落盘前确认**：展示目标路径 + 转换摘要（缓存判定结果；图片 N 张：区分命中台账未重复上传 / 变更或新增已上传 / 兜底比对沿用旧链接 / 未能比对默认沿用；正文转义还原 N 处；导不出的内容 K 处保留链接 / 不支持的元素清单）。
10. **落盘后写缓存、不做验证**：本地写入成功即完成，随后用脚本 `record-import` 把本次导入写入缓存（写失败只提示、不回滚文档）。不检查站点渲染、不回访图片链接（再次导入时为比对而回访旧链接发生在落盘前，不受此限）。
11. **清理临时文件**：过程中下载的图片、`doc read` 导出内容、比对用的中间结果全部删除。建议每次导入使用独立临时目录（如 `/tmp/dingtalk-import-<时间戳或ID>`），收尾整目录删除。`~/.coral-doc/` 缓存目录是跨会话的持久缓存，不要当临时文件删掉。

**保真导入是默认行为**，不会询问是否增强；发现的可增强点仅在最终汇报中顺带提及，使用者主动要求才改写。

### 幂等缓存

导入的「是否重复导出」判定与「图片是否重复上传」判定都落在一个全局缓存目录里：

```
~/.coral-doc/          # 仓库外，不随技能安装、不受 git pull / 重新 clone 影响
├── libraries/<库地址哈希>/<桶>.json    # 桶 = sha256(nodeId) 前 2 位；记录文档导到了哪个库、哪个路径
└── uploads/<实例名>/<桶>.json          # 桶 = 图片 sha256 前 2 位；记录图片上传后的长期链接
```

**分桶存储**：按键哈希前 2 位拆成 256 个小文件，每次导入只读写命中的那个桶，避免单个文件随文档量无限膨胀（万级文档时每桶也只有几十条）。

**脚本操作**：所有缓存读写都通过 skill 自带的 `scripts/imports_cache.py`（子命令 `hash` / `lookup` / `record-import` / `lookup-upload` / `record-upload` / `migrate`），不临场写代码、不手改 JSON。脚本内置原子写与损坏自愈（桶损坏时自动备份为 `.corrupt-<时间戳>` 后按空缓存继续，不静默丢数据）。

两张表的键设计不变：

- 文档表按**库绝对路径分组 + 钉钉 nodeId** 为键——同一篇钉钉文档导入到另一个库是全新记录，不会互相顶掉；再次导入是覆盖式更新，不产生重复条目。
- 图片表以**内容 sha256** 为键——图片改名、换位置、在别的文档里复现都能命中；以 **coral 实例**分组，避免跨实例复用链接导致图片 404。

缓存缺失时视为空缓存；脚本执行失败不阻塞导入（降级为无缓存并在汇报中说明）。旧版单文件 `imports.json` 用 `migrate` 子命令一次迁到分桶布局（原文件保留为 `.v1.bak`）。

#### 强制导入

想忽略缓存、重新导一遍（比如钉钉源文档已改但时间戳没变、或想把已有文档刷新一遍），在指令里带上强制意图即可，无需任何参数：

```
用 coral-doc 强制导入这个钉钉文档到文档库 ~/coral-book：
https://alidocs.dingtalk.com/i/nodes/xxxxxxxx
```

识别表达：**强制导入、强制覆盖、强制更新、强制重导、强制覆盖缓存、忽略缓存重新导入**，以及 `force import`、`force overwrite`、`force re-import`。

强制导入的边界：

- **会**跳过缓存判定、直接重新导入，并在落盘后**覆盖**该文档的缓存记录（路径、导入时间、源文档时间一并刷新）。因为记录以 nodeId 为键，同一文档在同一库下只有一条，覆盖是原地更新、不会留下重复条目。
- **不会**强制重传图片。上传台账是按图片内容哈希去重的，命中说明内容确实一致，重传只是白费存储；确实要重传时另外说「图片全部重传」或「强制刷新图片」。
- **位置**：没说位置就沿用记录里的路径，说了就用你给的并更新记录。

#### 位置复用

缓存记录同时是一份**存放位置记忆**。同一篇钉钉文档再次导入时，只要你没指定位置，就直接沿用上次的落盘路径，不再让你重新选一遍菜单；你明确给了新位置，则以你给的为准并把记录改到新位置。这条只在本库内生效——换一个库导入属于新记录，仍会按新文档选一次位置。

**事后挪动过文件也没关系**：缓存指向的旧位置找不到文件时，skill 会询问「继续导出到缓存记录的目录，还是重新指定目录」，落盘后无论哪种，记录的 `target` 都会更新为本次实际路径——强制重复导出同理，落盘后覆盖刷新记录。也就是说 `libraries` 记录永远跟着最新一次导入走，不会停留在已失效的旧位置。

## 本地优化模式

1. **读取文件**，识别**本地图片引用**（相对/绝对路径指向本地文件的 `![...](...)`；排除 http(s) 链接和已上传的 `/f/...` 远程链接）。
2. **有本地图片时询问**是否上传换取长期链接。删除规则：

   | 图片位置 | 上传成功后 |
   |---|---|
   | 文档库目录**内** | 改写引用，并**删除本地文件**（由 coral 服务统一提供） |
   | 文档库目录**外** | 只改写引用，**本地文件保留** |

3. **整理 front matter（默认执行，无需用户点名）**：重点是**修正字段名错误**——拼写或大小写错误（如 `tile`、`Data`、`Title`）按字段表修正为正确名称，对应不上已知字段的保留不动并在汇报中提示。关键字段缺失时补：`title` 从正文一级标题或文件名（去数字前缀）提炼。`date` 更新为当天最新时间（`YYYY-MM-DD HH:MM:SS`，缺失时补、已有时也刷新）。`_index.md` 缺 `icon` 时给出 1-2 个匹配目录主题的 Iconify 名建议，使用者可采用、换一个或选择不加。`weight` 属特殊字段，默认不补不改（取值应由使用者决定），缺失时仅在汇报中提示。其余字段（`permalink`、`draft`、`archetype`、`url`、`disableToc`、`remote_url`）一律不动；没有 front matter 时新建 YAML 头（首行 `---`），已有 TOML 头（`+++`）保持 TOML；无需调整时汇报说明。
4. **其他优化按使用者意图执行**：说了优化什么就做什么（格式修正、链接修复、coral 能力美化等），没提到的不会擅自做。目标落在文档库内时，遵循 front matter 与站内链接约定。
5. **落盘前确认**：展示改动摘要（图片 N 张中新上传 M 张、命中台账未重复上传 C 张、K 张库内文件已删除、失败原因；头信息改动清单：修正的字段名、补上/更新的字段、icon 建议值——使用者可选择不加；其他优化项清单），确认后写回原文件并汇报。上传失败的图片保留原引用并说明。

## coral markdown 能力速查

完整语法与语义见 [references/coral-markdown.md](references/coral-markdown.md)，此处只列速查。**只使用这份清单里的能力**——清单外的 shortcode 或 HTML 标签会被 coral 原样输出、不会渲染，除非仿写的样板本身就在用。

| 能力 | 写法要点 |
|---|---|
| front matter | 首行 `---` 为 YAML（`+++` 为 TOML），字段全部可选 |
| 提示块 | `{{% notice style="caution" title="风险提示" %}}...{{% /notice %}}`，`style` 白名单：`tip`/`info`/`note`/`caution`/`warning`/`important`/`danger`/`error` |
| 选项卡 | `{{< tabs >}}` + `{{% tab title="X" %}}...{{% /tab %}}`，首个 tab 默认 active |
| 子页目录 | `{{% children sort="weight" %}}`，适合章节目录页 |
| mermaid | 代码围栏，语言标注写 `mermaid`；仅围栏形式有效，没有对应 shortcode |
| 数学 | 块级 `$$...$$`（默认启用）、语言标注为 `math` 的围栏；行内 `$...$` 需服务端 `[render].inline_math = true` |
| 代码高亮 | 始终标注语言（`sql`、`json`、`yaml` 等），不写裸代码块 |
| GFM | 表格、任务列表、删除线、autolink；内嵌 HTML 原样透传 |
| 站内链接 | 写 `.md` 相对形式（`./detail.md`），coral 自动重写为站内 URL 并剥掉扩展名 |

**结构约定**

- 一级菜单 = 根目录下每个子目录（取其 `_index.md` title）+ 根级文档。
- 分支页回退链：`_index.md` > `index.md` > `readme.md`（不区分大小写）。
- 同级排序四级链：① `weight` 升序（无则沉底）→ ② 文件名数字前缀（`1.入门.md`）→ ③ `date` 倒序 → ④ 文件名序。
- 新建目录若需作为菜单节点展示，需创建 `_index.md`。

## 维护指南

**仓库是唯一源头。** 内容以 GitHub 上的 `master` 为准，安装目录是它的克隆，升级走 `git pull`（见「安装」一节）。改动流程是：改 → 提交 → 推送 → 使用方 `git pull`。只改本地工作副本而不推送，已安装的那份不会跟着变。

**改动时的联动关系**

- `SKILL.md` front matter 的 `name` / `description` / `when_to_use` 共同决定**是否被自动唤起**。当前三者写的是「仅手动调用」，改动它们会直接改变唤起行为，改后需同步本文档的「调用方式：仅手动唤起」一节。
- 新增或修改 coral 渲染能力，改 `references/coral-markdown.md`，并同步本文档的「coral markdown 能力速查」表与 `SKILL.md` 的美化清单。
- 导入流程的命令或上传接口有变化，改 `references/dingtalk-import.md`；摘要格式变化需同步 `SKILL.md` 的对应步骤。
- 缓存的布局或子命令有变化，改 `scripts/imports_cache.py`，并同步 `references/dingtalk-import.md` 第 2 节与本文档的「幂等缓存」一节。
- 保持约束：只使用 `references/coral-markdown.md` 列出的能力；不绑定特定团队清单或固定路径，也不绑定某个具体 agent。

**本地开发时若不想推送到远端再拉**，可以直接把工作副本同步到安装位置，省一次提交：

```bash
rsync -a --delete --delete-excluded --exclude '.git' --exclude '.gitignore' --exclude '.zcode' --exclude '.codex' \
  ~/coral-doc/ ~/.agents/skills/coral-doc/
```

两个注意点：这条命令产出的是 `.git` 被删掉的「纯文件」副本，**只能用于非克隆安装**——对克隆的那份执行会删掉它的 `.git`，`git pull` 从此失效；另外 `--exclude` 只负责不发送，目标端已残留的同类文件要配 `--delete-excluded` 才会被一并清掉。

## 已知限制

- 钉钉仅支持普通文档（adoc）导入，表格/画板/白板/多维表需先在钉钉中转为文档。
- 行内数学公式默认关闭，需服务端开启 `[render].inline_math`。
- skill 只负责生成并落盘文档，不做落盘后的站点渲染或链接可用性校验。
- 钉钉返回的图片是短时效签名 URL，不走上传换链会很快失效。
- 幂等缓存以**库绝对路径**为分组键：库目录被移动或重命名后旧记录不再命中，会按新导入处理。
- 缓存是**本机目录**（`~/.coral-doc/`），不跨机器共享：换机器导入同一篇文档仍会走完整流程，图片是否重复上传也取决于各自机器的台账。
- 「源文档是否已更新」依赖钉钉返回的最后修改时间；拿不到该字段时不会自动跳过，而是询问使用者。
